# Protected synthetic session acceptance

Continues PR44 runtime `8be9917306beaca7a4f102375379592c77a9ecd2`. This slice adds acceptance coverage; application runtime, market policies, provider selection, order permissions, exits and risk rules are unchanged.

The new session test runs the existing session runner and complete v2 cycle shell with the native Alpaca entry-context adapter, schedule parser/cache, sector context and decision/refresh checks. Provider replies and elapsed time are synthetic. A fixture broker records attempted intents and always refuses them; there is no order transport. The existing `scripts/validate_offline.py` independently removes inherited credentials, isolates data roots, and denies socket/DNS and unapproved subprocess operations.

Five scenarios execute 39 complete cycles: an 18-cycle warm/expired-cache session, an 18-cycle failed-refresh session, a cold FOMC failure, a 33-second collection delay with fresh quote revalidation, and a 93-second stall that fails entry freshness. Cached schedules retain their original receipt time. Expired successful data is not substituted for a failed calendar refresh. A cold unavailable calendar cannot reach the fixture broker. Existing setup-attempt and volatility checks remain active during repeated cycles; the fixture does not remove them to manufacture repeated admissions.

The session currently waits its configured interval after completing each cycle. With six seconds of synthetic cold calendar work and a 60-second interval, the next cycle starts 66 seconds after the first. This proof does not claim a hard 60-second start cadence, measured provider latency, live-market throughput, or a guaranteed observation polling frequency. The 33-second case may be admitted only after the normal fresh-quote checks; the 93-second stale trigger is refused.

Focused protected acceptance passed all five scenarios, zero errors/skips and zero prohibited operations. A related replay including the existing session-runner and sector/schedule runtime cases passed 22 tests. Independent review replaced an overly broad rejection assertion with the exact `entry_stale_completed_bar` reason and underlying-bar detail. The 33-second case now asserts its measured bar age, the existing 90-second limit and zero-age refreshed stock/option quotes; the stale case proves rejection before quote refresh. Receipts retain cycle starts/finishes, provider reads, schedule capsules, admission evidence, refused fixture-intent counts and actual test wall time. Source identity and final evidence paths are recorded in the task's continuation checkpoint. Earlier failing fixture iterations are retained; they are not product failures or accepted proof.

No native Gemini tool or executable was available for the separate required external review. Gemini-before-merge, earnings coverage, whole-market ranking, live provider cadence, genuine fills and production release remain open. No broker/account credentials, real account/order endpoints, deployment or trading settings were touched. `entry_advantage_established=false`.
